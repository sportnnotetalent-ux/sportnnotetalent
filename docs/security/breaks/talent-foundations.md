# Talent foundations (schools, memberships, students, parents) — break it first

2026-11-09. Break-it review (quality mandate step 4) of `supabase/migrations/20261117120000_talent_foundations.sql`, spec `docs/talent/schema-foundations.md`, tests `tests/db-talent-foundations.test.mts`. Nothing here is fixed; this is the list.

Method: read the migration and the existing pieces it leans on (`players` RLS and column grants, `guard_player_write`, `players_view`, `claim_player_by_phone`, `phone_login_attach_player`, `delete_account_data`, `phone_key`, `org_*` policies). Breaks marked CONFIRMED were reproduced in PGlite with a throwaway probe: `/private/tmp/claude-501/-Users-macbookpro-Desktop-rudy-SportnNote-Talent/d8ad1505-7337-4f65-8e7c-412321e29e92/scratchpad/probe-talent-foundations.test.mts` (move it into `tests/` to run; probe ids in brackets below). No live system was touched.

What holds up (tried, did not break): anon and signed-in strangers cannot call `talent_phone_allowed` or any write RPC (permission denied; anon `talent_attach_me` denied); direct `insert` into `talent_memberships` is denied; a stranger gets "No such membership" for random ids; the school-row lock plus re-counting in the triggers serialises concurrent cap checks; an Admin cannot add or remove an Org Leader; a removed Admin cannot read `talent_students`, `talent_memberships` or call the RPCs; parent phones are not copied onto `players` (so `claim_player_by_phone`, `phone_login_attach_player` and `my_claimable_player` do not match a student by the parent's number); anon sees none of these children.

Severity: P0 = children's data or sign-in broken by a stranger; P1 = children's data exposed or taken by an insider or a mistake, or a cross-school/sign-in failure; P2 = real but bounded, or needs a rare condition.

## Recommendation to the Director

BLOCK. TF1, TF2, TF3 and TF10 each affect children's names, birth dates and parents' contacts and are confirmed. TF8 affects sign-in for every school a user belongs to. The common cause is that a student is an ordinary `players` row governed by the old creator-based rules, not by `talent_memberships`. Findings need an Engineering hand-off with a failing test first (the Suggested test column), then a 500-user sim.
