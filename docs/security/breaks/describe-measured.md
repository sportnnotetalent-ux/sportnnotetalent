# Measured sports: splits, take-overs and DQ reasons fold to "✓ Saved" with Done (wave 2) — break it first

2026-11-08. Wave 2 of docs/sport-expert/defaults-on/PLAN.md brings the badminton describe card (`src/components/DescribeCard.tsx`, describe-card.md) to the timed-race sports: athletics, swimming, cycling, rowing and canoe. Item 9 of docs/sport-expert/defaults-on/measured.md names three places with no clear finish. Splits save on blur and stay open for good once one is saved (`ResultsEventScreen.tsx` SplitsField). Relay take-overs (`RaceDepth.tsx` TakeoverField) are always open. The swimming and athletics DQ-reason chips stay open while the row is DQ. Each now gets the card: a "✓ summary" line, a full-width **Done** (it reads **Skip** when nothing is entered), a fold to "✓ Saved · 3 splits · Edit", and the next entry opens fresh. Typed values still save on leaving the box, exactly as before. Done and Skip only add a save of a valid value that has not been saved yet. Golf's "Next: hole ▶", weightlifting's lights and "Last:" line, and the shooting / archery confirm sheets already finish clearly, so they stay as they are. The pure parts live in `src/data/results/measuredFold.ts`; the tests are in `tests/describe-measured.test.mts`.

| # | Break | Kind | Fix |
|---|---|---|---|
| DM1 | A split is typed and Done is tapped while the box still has focus (native keeps focus on a tap), so blur never fires. The card folds and the split is lost. | Data loss | Done runs the same commit as blur first (`doneStep`). A valid typed value that hasn't been saved is saved, then the card folds. Take-overs work the same way. Tested, and in the simulation. |
| DM2 | An unreadable split ("1:7x") and then Done: the card folds, the error is hidden, and the scorer thinks it saved. | Data loss / clarity | `doneStep` refuses to fold while a value can't be read. The card stays open with its error line. Tested. |
| DM3 | Blur saves, and Done a moment later saves the same list again (the row hasn't reloaded yet). | Integrity | `doneStep` takes the last list sent and doesn't send it twice. Tested. |
| DM4 | The lanes are reordered (moved, or the draw redone), and the "✓ Saved" fold moves to the wrong athlete because it followed the position. | State | The fold is remembered per entry id and phase (`foldKey(kind, phaseId, entryId)`), never by lane or index. Tested, and in the simulation (random reorders). |
| DM5 | Relay leg swap: the team changes its running order, and the folded take-overs read as if they belonged to a swimmer. | Data | The take-overs stay with the exchange (legs 2–4), as stored. The summary names the leg ("L2 0.21 · L3 0.18"), and the fold is per team entry. Tested. |
| DM6 | An early take-over (before −0.03 s) is folded away, and the ⚠ judge line and "Judge confirms: DQ" chip disappear with it. | Safety | The ⚠ line and the DQ chip stay visible under the folded line. Tested (source). |
| DM7 | A DQ reason is removed after Done: the chip is untapped, the athletics rule box is retyped (the reason goes stale), or DQ is toggled off and on. The fold then shows "✓ Saved · nothing picked", or keeps a stale reason. | State / clarity | The summary is always read from the saved row. A "saved" mark with no summary opens again (`foldMode`). Changing the DNS / DQ status clears the mark. Tested, and in the simulation. |
| DM8 | Skip hides the card with no way back, so splits, take-overs or a reason can't be added later. | Usability | A skipped card shows a "＋ Splits" / "＋ Take-overs" / "＋ DQ reason" chip that opens it again. Tested (source). |
| DM9 | Locked event: a fold's Edit would reopen boxes on a completed round. | Integrity | Every card renders only under the screen's `editable` gate (a completed phase is not editable), as before. Tested (source). |
| DM10 | Heat → final: the final's rows open folded because the heat's marks carry over. | State | Keys carry the phase id, and moving to another round remounts the screen (`nav.replace`). A new phase or heat entry opens fresh. Tested. |
| DM11 | Screen reader: the cards all say "Describe the last play", and the ＋ chips are bare symbols. | A11y | Each card's title names what and who ("Splits · Asha", "Take-overs · Blue relay", "DQ reason"). The summary line is plain text. The ＋ chips have labels ("Add splits for Asha"…). The Done / Skip / Edit labels come from the shared card. Tested (source). |
| DM12 | Results, rankings, records, PBs or commentary change because Done saved something different from blur. | Integrity | Done calls the same `onChange` / `onSave` with the same list the blur would send. Nothing else is written. The simulation checks marks, statuses and the ranking order before and after. |
