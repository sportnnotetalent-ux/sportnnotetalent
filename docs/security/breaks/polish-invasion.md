# Invasion polish (wave 4): break it (2026-11-08)

Wave 4 of docs/sport-expert/defaults-on/PLAN.md for football, hockey, ice hockey, rugby union and rugby league. Three items:

1. Ice hockey faceoff zones become a non-blocking `DescribeCard` (describe-invasion DI16), so `trackFaceoffZones` can default ON (defaults-on-invasion DOI9).
2. A correction that deletes the only event of a kind in a completed match must clear that key on the stat line (no-false-zeros-invasion NZI15).
3. Football's goal re-entry from the timeline keeps the assist and the goal's detail, as the other four codes already do (`carry`).

The points were listed before any fix. Each has a failing test first in `tests/polish-invasion.test.mts`, plus a 600-scorer simulation in the same file.

| # | Break | Kind | Fix |
|---|---|---|---|
| PI1 | **The zone panel blocks scoring.** With zones on, every faceoff tap replaces the controls with a three-button zone panel (`mode: 'foZone'`) until the scorer answers or skips. | Slow scoring | The faceoff logs at the winner tap (TALLY, no zone). The zone is attached after on a `DescribeCard` keyed by the faceoff's id (chips OZ / NZ / DZ named by the end, Done / Skip, "✓ Saved · … Edit"). The `foZone` flow is gone. |
| PI2 | **The zone step credits the wrong centres.** A separate zone step could credit only the winner, or credit the zone keys twice, or forget the loser's mirror zone. | Wrong stats | New engine step `FO_ZONE` (`foZoneAction`, ref = the faceoff). Its credits are `creditDiff` of the engine's own `eventCredits` before and after, so the winner gets `faceoffWins<Zone>` and the loser `faceoffLosses<mirror>`. TALLY + FO_ZONE credits exactly what the old one-step TALLY-with-zone did, per player. |
| PI3 | **Old logs change.** Saved matches have TALLY actions with the zone on the payload. If the reducer stopped reading it, old zone figures would vanish. | Data | The TALLY reducer is unchanged (still reads `payload.zone`). An old one-step log and the new two-step log give deep-equal events, totals and team figures. |
| PI4 | **A hostile or stray zone step.** FO_ZONE aimed at a hit, a goal, a removed faceoff, the other side's faceoff, an unknown zone, or with no ref. | Wrong stats | Builder returns null and the reducer leaves the state unchanged for all of them. |
| PI5 | **Changing or clearing the zone.** Edit on the card: OZ → DZ, or clear it. A naive step would add the new zone's keys without reversing the old ones. | Wrong stats | Credits are the before/after difference: OZ → DZ reverses `faceoffWinsOz` / `faceoffLossesDz` and adds the new pair; `zone: null` reverses them. Undo of the step restores the previous zone. |
| PI6 | **The faceoff is removed after its zone.** A correction removes a faceoff that has a zone attached. | Wrong stats | `removalActions` uses `eventCredits(e)`, which includes the zone keys, so all of them reverse. Tested on totals. |
| PI7 | **The last faceoff's zone after the final horn.** The game ends right after a draw; the card is still open. | Lost data | `FO_ZONE` is accepted on an ended match (like `GOAL_DETAIL`, DI11). |
| PI8 | **False zeros from zones.** A faceoff whose zone was never attached must not write zone keys, and the zone step's own credit must stamp the zone keys as tracked. | Wrong stats | Zone keys are tracked only once one faceoff carries a zone (`zonesTracked`, unchanged). The builder stamps `iceTrackedKeys` with the patched faceoff. |
| PI9 | **Default ON changes old matches.** Flipping `trackFaceoffZones` in `ICE_HOCKEY_STATS_DEFAULTS` must not turn zones on for a saved match, and Reset / "N changed" must agree. | Data | Only the constant moves (the format field and live `defaults` read it). `init` keeps its OFF fallback, so old matches stay off. |
| PI10 | **A stale card.** The card must follow the newest faceoff, vanish when its faceoff is undone or removed, and hide while a correction is open. | Wrong UI | Card keyed by the faceoff id, looked up in the events each render; a newer faceoff replaces it; hidden while `editAt` is set. |
| PI11 | **Undo says nothing.** Undo of the zone step needs a name. | Wrong UI | `iceHockeyUndoLabel` names FO_ZONE "faceoff zone" (or "faceoff zone removal"). |
| PI12 | **NZI15: a stale key after a correction.** In hockey, ice hockey, rugby union and league the totals own the whole line. A correction that deletes the only event of a kind (the only penalty-corner goal, the only hit, the only tackle) in a completed match leaves no player with that key, so the sync no longer "owns" it and the old value stays on the line. | Careers | Each of the four sports declares every key its totals can write (`STAT_TOTALS_KEYS` in totals.ts, plugin `statTotalsKeys`). `planStatSync` takes those as owned too, so a key on the line that the totals no longer produce is set to 0 (contract rule 4: a missing owned key reads 0). |
| PI13 | **The fix wipes keys it does not own.** Appearance lines (`starts`), or a key from another writer, must not be cleared. | Data | Only the declared keys are cleared; anything else on the line is untouched. Tested with `starts`. |
| PI14 | **Football is partial.** Football's line is mostly live deltas; clearing its unproduced keys would wipe goals and tackles. | Data | A partial sport (`statTotalsPartial`) declares nothing and gets no extra owned keys; behaviour unchanged. |
| PI15 | **The SD-69 key-limited resync.** `resyncSportLines(…, { keys })` must write only those keys. | Data | The extra owned keys are intersected with `keys`. |
| PI16 | **The declared list drifts.** A new stat added to a sport's totals but not to its list would go back to staying stale. | Careers | Tested: in 600 simulated matches every key the four totals produce is in that sport's list. |
| PI17 | **Football re-entry loses the assist.** ✎ Edit on a goal re-logs it with the new scorer and no assist. | Lost data | The goal flow carries the old assister (by id). The re-entry fires the GOAL and then the ASSIST with the new goal's ref. If the new scorer is the old assister, the assist is dropped. |
| PI18 | **Football re-entry loses the goal detail.** Goal type, body part, zone, big chance and situation are reset to open play. | Lost data | The same carry holds them; the re-entered GOAL carries them (a situation only where it fits the type, as before). |
| PI19 | **The assist lands on the wrong goal.** The re-entered goal is appended after later goals; an assist by "latest goal" or a wrong ref would attach elsewhere or be dropped while still credited. | Wrong stats | The ref is the re-entered goal's own id (the state's `seq + 1` after the held removal, which `view` already includes). Tested on a match with later goals of the same side. |
| PI20 | **A legacy name-only assister.** Old logs may name the assister without an id. | Data | IDs-only scoring: only an id is carried; a name-only assist is not re-created (as for the other codes). |
| PI21 | **Voice re-entry.** The spoken scorer step (scorer → type → body) would drop the carry. | Lost data | With a carry, the spoken scorer re-enters the goal straight away with the carried detail. |
