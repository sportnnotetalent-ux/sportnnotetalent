# Stats to track ON for new events: the measured sports — break it first

2026-11-08, wave 3 of `docs/sport-expert/defaults-on/PLAN.md`, for golf, athletics, swimming, cycling, rowing, canoe, archery, shooting and weightlifting. The specialist's list is `docs/sport-expert/defaults-on/measured.md`:

- **Golf:** putts, fairways, bunkers, up and downs, penalties and first-putt length ON for a new round. Driving distance stays OFF (typed, needs a rangefinder).
- **Athletics, swimming, cycling, rowing, canoe:** every timing extra stays OFF (it needs equipment). Swimming 50 m splits stay ON, as before.
- **Weightlifting:** jury reversals ON. Referees' lights stay OFF.
- **Shooting:** the −2 penalty button stays OFF.
- **Archery:** arrows per archer in team matches ON.

The rule: **only new events and rounds change**. Anything that already exists reads exactly as it did. Listed first, without fixing; each fix then starts from a failing test in `tests/defaults-on-measured.test.mts`.

| # | Break | Kind | Fix |
|---|---|---|---|
| DOM1 | Flipping `default: false → true` for `wlJury` / `archTeamArrows` in `precisionRules.ts` switches them on for **every existing event**, locked ones included: `ruleOf` falls back to the default when a phase stored nothing, and `phaseRules` never stores a value equal to the default (`competitionRules.ts` `ruleOf`, `phaseRules`). | Old event changes | `default` stays `false` (the read fallback). A new field `newEvents: true` says what a NEW tournament starts on. `withNewTournamentPoints` / `newTournamentFormats` (the creation choke point, used by Create, Quick and a sport added in Edit) write it into `formats[sport]`, so `phaseRules` copies it onto new phases. A phase with `rules: {}` (or none) still reads OFF. Tested. |
| DOM2 | An old tournament (nothing stored) adds a new event or the next round of an old event: if the new value leaked in from anywhere but creation, one meet would mix ON and OFF. | Old meet changes | New phases of a tournament read the tournament's `formats[sport]` (`rulesForNewPhase`), which an old tournament never had stamped, so they stay OFF. Editing an existing tournament never re-stamps its sports. Tested. |
| DOM3 | A standalone event (no tournament) has no `formats` to stamp, so it would never get the new defaults. | Missed default | `createResultsEvent` without a tournament takes `newEventRules(sport)` as the first phase's rules. Later rounds copy the phase's rules (`{ ...f }`). Tested (source + pure helper). |
| DOM4 | Heat → final: a new event's final must keep the heat's ON; an old event's final must keep the heat's OFF; an archery team bracket and a shooting medal match must keep them too. | Carry-over | Every advance path copies the phase format (`{ ...f, … }`, `advanceToBracket`, `advanceToShootMatches`), and `rules` rides along. A phase made by `insertPhase` without rules reads the tournament, which is DOM2. Tested (source). |
| DOM5 | Golf: changing the phone fallback (`GolfRoundScreen.tsx` `phoneTrack` `[]`) or `effectiveTrack` would make a round **already in play** start tracking mid-round. | Round in play changes | Only the setup's starting value changes (`GolfRoundSetupScreen.tsx`: `null` → `NEW_ROUND_TRACK`). The phone fallback stays `[]`, `effectiveTrack` is unchanged, and an old round's `format.track` (absent) still reads the phone. Tested. |
| DOM6 | Golf round 2 of an old tournament ("Next round", `nextOf`) or a "Run it again" round carried from an old edition: the new seed must not override what round 1 had (each marker's phone). | Carry-over | Both paths already call `setTrack(roundTrackOf(last.format))` after the seed, which puts back `null`. Unchanged and tested (source). |
| DOM7 | **Reset** ("Back to standard" on the Competition rules screen) sets every rule to `r.default`, so on a new tournament it turns jury reversals and team arrows OFF again, and the "· standard" mark sits on Off. | Reset undoes the defaults | Reset and the "standard" mark use `standardOf(r)` = `newEvents ?? default`. Tested. |
| DOM8 | The organiser picks **Off** for jury reversals: the screen stores a value equal to `default` as "unset", so nothing is saved. A Run-it-again copy or a sport re-seeded through `withNewTournamentPoints` then turns it back ON. | Choice lost | A rule with `newEvents` always stores the organiser's value (like an `existing` key); `phaseRules` still skips `false`, so phases read OFF. `changedRules` (the summary line) compares with `standardOf`, so a new tournament on the new defaults shows no "changed" rules. Tested. |
| DOM9 | Zeros, golf fairways: a card kept with Fairways (now ON) writes `firLeft: 0 / firRight: 0` even when no fairway was tapped, and the round stats show "Missed left 0 · Missed right 0". | False zero | `firLeft` / `firRight` are written only once a fairway direction was entered on a par 4 / 5 hole of the card. Tested. |
| DOM10 | Zeros, the rest of golf: with putts, bunkers, up and downs, penalties and first-putt length ON and nothing entered, a card must write no stat a marker never recorded (wave 1 NZG7–NZG9 made this true; the new defaults make it common). | False zero | Re-checked, not changed: the 600-user simulation creates rounds on `NEW_ROUND_TRACK` with random partial entry and checks no tracked key exists for a kind with no entry, and no stat-sheet row reads 0 of nothing. Tested. |
| DOM11 | Zeros, precision: jury ON adds a "Last: … · ⚖ Jury reverses" line, team arrows ON keys arrows archer by archer. Neither writes a count when nothing happened (`juryReversals` etc. come from attempts). | False zero | Checked in the simulation: results with the new rules equal results without them (same totals, places and records). Tested. |
| DOM12 | Misleading commentary: if only the winner's splits are typed, `winnerSplitStory` ranks the winner against nobody and says "led at every split" (`raceDepth.ts`). `fastestFinish` likewise names the only runner with splits as "fastest finish". | Misleading | A split point counts only when at least two finishers have a time there; with none, no story. `fastestFinish` needs at least two finishers with the same last segment. Tested. |
| DOM13 | A timing extra (reaction, lap times, relay legs, chip times, take-overs, cycling / crew intermediate times) or lights / the −2 penalty / driving distance switched ON by mistake puts a typed box on every row or changes the main entry. | Wrong default | Pinned: each stays `false`; swimming splits stay `true` in both homes (`swimming/meta.ts`, `competitionRules.ts`). Tested. |
| DOM14 | The "Use the new defaults" button needs to find these keys. Measured precision rules are competition rules, not format fields, and golf's track is round state. | Discoverability | Every precision stats rule keeps `group: 'Stats to track'`; `MEASURED_NEW_DEFAULT_KEYS` (`precisionRules.ts`) lists the precision keys and `NEW_ROUND_TRACK` (`golf/track.ts`) the golf ones. Tested. |
| DOM15 | Hostile stored values: `wlJury: 'yes'`, `archTeamArrows: 1`, a `track` with junk keys. | Robustness | `ruleOf(...) === true` and `cleanTrack` already ignore them; the organiser's stored keys win over the stamp. Tested in the simulation. |
| DOM16 | Results change: an event scored before and after the change must rank the same. | Replay | The simulation ranks every event with stored-nothing rules and with the new rules and compares the places and totals. Tested. |
