# Tennis doubles: who hit the winner: break it (2026-11-08)

Wave 4. Founder rule: in singles the credit is obvious (an error by A means B won). In **doubles** (A & B vs C & D) a winner by C & D could have been hit by C or D, so the after-point card asks **"By:"** which one; an error already asks which of the two opponents erred. This builds player-wise stats alongside the team stats.

The five other racket sports have done this since racket-depth RD4 (`pd.by`, `PointDetailRow.tsx`). Tennis dropped `by` on purpose (`validPd`: "tennis unchanged"; `PointCapture.tsx` `WINNER_BY = false`, describe-done DD12). This pass brings tennis level, **new matches only**: a point without `by` credits exactly as before.

**Process:** quality mandate step 4. Listed after reading the code and **before** any fix. Each fix then gets its own failing test first (step 5).

**Status: Fixed** (every point Fixed or Holds; TH4 accepted as racket-depth RD11). Tests: `tests/tennis-doubles-hitter.test.mts` (27; 14 failed before the fix). Simulation: 600 random tennis matches in the same file (singles and doubles, at least 10,000 points and 1,500 players asserted, with hitters, changed hitters, forged and hostile hitters, skipped cards and undos). Invariants: team tallies unchanged by the hitter; per-player winners / service winners plus the side-level credits nobody can take equal the team's; with `by` stripped every credit equals a frozen copy of the old credit; a timeline replay keeps every hitter. Pinned test updated on purpose: `racket-depth.test.mts` RD6 asserted that tennis drops `by` (the old behaviour).
