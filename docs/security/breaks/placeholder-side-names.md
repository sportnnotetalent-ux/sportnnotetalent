# A quick game's placeholder side keeps "Player B": break it (2026-11-03)

**Bug (founder, live app):** Home's "Just finished near you" showed a pool match as "Vivek C 1–0 Player B" although the opponent is a known person. A quick friendly started with an empty side creates an ad-hoc placeholder team ("Player B", "Pair A", "Team A"; short "B"). When the real person or pair is added later ("＋ Add / invite a player" on the live screen), the team keeps the placeholder name, so every card, feed, share text and notification says "Player B".

**Process:** quality mandate step 4. Points listed first, without fixing; each fix then got a failing test (step 5).

| # | Break | Status |
|---|---|---|
| PS-01 | **Adding the player to a "Player B" side never renames it.** `invitePlayer` → `appendRoster` writes the roster only. | **Fixed:** `invitePlayer` / `setTeamRoster` → `renamePlaceholderSide` (repos.ts) with `placeholderRename` (core/quickGame.ts): the player's name, short code from `entryShortName`. |
| PS-02 | **Adding both partners to a "Pair A" side never renames it.** Same path; the pair's name is never written. | **Fixed:** same path; the pair is named with `entryName` ("Ravi Kumar / Arjun Shah"), the form the server's `teams_entry_names` trigger recognises. The scorer still shows "Ravi / Arjun" via `entryDisplayName`. |
| PS-03 | **Matches already played show "Player B"** for a placeholder side that has its real player on the roster; no read rebuilds the name. | **Fixed:** `revealEntryNames` (every match read: Home feed, near you, Matches, match, search) rebuilds a placeholder side's name and short code from its roster (`placeholderEntryIds`). No data migration. |
| PS-04 | **Children's names (privacy).** A rename written with a name the server's `teams_entry_names` trigger doesn't recognise as an entry (e.g. the pair's first names "Ravi / Arjun", or a name taken from client input) is stored unmasked, so a child's name would show to everyone. The display fallback must also read names through `players_view` (full names only for the child's circle, initials for everyone else), never from a stored or typed name. | **Fixed:** both paths read names from `players_view`, never typed input; the rename always matches the trigger, which masks a child in the stored copy (the simulation checks it). |
| PS-05 | **A real team must never be renamed or relabelled:** a team the user named "Player B" (not ad hoc), a placeholder the user already renamed, or a "Team A" side (a team keeps its name until the user gives one). | **Fixed:** `isQuickPlaceholder` (ad hoc + exact name) gates both; "Team X" is never renamed (tests + simulation). |
| PS-06 | **Partial / odd rosters:** "Pair A" with one partner so far, "Player B" with two people, duplicate or blank ids, a player whose name can't be read — none may produce a half name ("Ravi / undefined") or a blank one. | **Fixed:** "Player" needs exactly 1, "Pair" exactly 2 distinct non-blank ids and readable names; otherwise unchanged. |
| PS-07 | **Rename failure must not lose the add:** the roster write succeeds even if the rename write is refused (RLS, offline); the rename is best effort. | **Fixed:** the rename runs after the roster write, in try/catch (reported, never thrown). |
| PS-08 | **Short code** stays "B" after a rename (score strips show "B"). | **Fixed:** the short code follows (`entryShortName`), in the rename and the fallback. |
| PS-09 | **Cost:** the fallback must not add a read per card; only teams whose name looks like a placeholder are looked up, in one read, cached. | **Fixed:** only "Player/Pair A/B" names are looked up, in one chunked read, cached a minute; the rename reads nothing for rosters outside 1–2. |
| PS-10 | **Who can call it:** the rename is a normal `teams` update under the same RLS as the roster write (guard_team_write); no new permission, function or grant. | **Accepted:** nothing new to call. |
| PS-11 | **The live screen keeps the names it was opened with** (route params): title "Vivek C vs Player B · Match Details", Summary result card "VC / B", share text and notifications. | **Fixed:** `placeholderParamsPatch` updates the params when a placeholder side loads under its real name; adding a player reloads the match. |

Tests: `tests/placeholder-side-names.test.mts` (18), simulation `tests/sim-placeholder-side-names.test.mts` (600 sides). App-only change: no migration, no edge function.
