# Student lists: break it

**Feature:** bulk student upload (commit `b2eec10`, migration `20261028100000_student_lists`, edge function `school-parent-request`).

**Process:** quality mandate step 4. Every point below was listed **before** anything was fixed; each is then fixed one by one with a failing test first (step 5), or accepted with a reason.

**Severity:** High = children's safety or privacy, or silent data loss. Medium = integrity, cost or availability. Low = edge cases.

| # | Severity | What breaks, and how | Status |
|---|---|---|---|
| SL-01 | High | **A fake "school" can phish parents.** Anyone can create a school community, because verification is optional. They upload rows with a child's name, date of birth and parent contact, found on social media. SportnNote then emails the real parent: "*Greenwood High* would like to add Asha to its students". If the parent agrees, the fake school becomes part of the child's circle: full name, date of birth for confirmations, and the child's teams. The match result is also an oracle: it confirms that a given child is on SportnNote. | Fixed: only a verified school matches children elsewhere (`roster_outside_match` runs only when `verified`); an unverified school's rows are "new". Demo matcher too. |
| SL-02 | Medium | **Parents can be harassed after saying no.** After a parent declines, the school re-uploads the list. That makes a new invite and sends a new email, and the cycle can repeat. | Fixed: `roster_outside_kind` returns "declined" for 180 days; the preview says why and does nothing. |
| SL-03 | Medium | **Email volume and cost.** One call can create up to 3,000 invites and emails, and 20 calls an hour are allowed. There's no daily cap per school, so a bad list or a script burns the email quota (Resend) and floods inboxes. | Fixed: at most 100 requests a call (`sent_now`) and 500 a school a day (`today_count`). |
| SL-04 | Medium | **A child can decline for their parent.** A child with their own account sees the school's invite in the app. The block stops them accepting but not declining, so the parent's decision is taken without them. | Fixed: `guard_roster_invite_answer` blocks both accept and decline by a possible minor. |
| SL-05 | Low | **The anonymous rate limit is keyed on the code's first 4 characters.** An attacker changing codes gets a fresh bucket every time. Brute force is still out of reach (80-bit codes), but each try writes a row to `rate_limit_hits`, so the table can be bloated. | Fixed: `request_subject()` keys anonymous tries on the caller's address (`x-forwarded-for`). |
| SL-06 | Low | **Retention.** `org_parent_requests` keeps the parent's email address forever, even after a decision or expiry. That goes against DPDP data minimisation. | Fixed: `target_email` is cleared on a decision, and codes 30 days past their end are purged. |
| SL-07 | Medium | **A big school's first list can time out.** For each row that isn't matched by admission number or name, step c compares the first name and contacts against every member, with no index. A 3,000-student first upload sent in one 3,000-row call could take about 9 million name evaluations and exceed the API statement timeout (around 8 s). The check then fails exactly when it matters. | Fixed: the app sends 500 rows a call (`MATCH_CHUNK`), and first names are indexed (`players_roster_first_idx`). |
| SL-08 | High | **Silent data loss in a race.** The save calls `setOrgMembers(full list)`, which deletes any member missing from the list it was given. If another admin adds a member between our read and the save, that new member is deleted. | Fixed: the import uses `upsertOrgMembers` (never deletes) and writes only the rows it changes. |
| SL-09 | Medium | **A partial failure brings duplicates back.** New profiles are created first and the memberships are written afterwards in one call. If that call fails (network, timeout), the new profiles exist but aren't at the school. Running the list again doesn't find them, so it creates them again. | Fixed: each new student is upserted into the school right after their profile is created. |
| SL-10 | Medium | **Files can freeze the browser.** An `.xlsx` zip bomb (a few KB that expands to gigabytes) is inflated fully in memory. A 100,000-row paste is parsed and planned in one go. Either can freeze or crash the admin's tab. | Fixed: at most 5,000 rows (`MAX_ROSTER_ROWS`, `tooMany`); Excel limits of 15 MB per file and 40 MB per part; inflation stops at the limit. |
| SL-11 | Low | **The sheet reader can slow to a crawl.** Its regex scans to the end of the file for every unclosed `<c`, so a malformed sheet takes quadratic time. | Fixed: rows and cells are split, not regex-scanned, so it stays linear (20,000 unclosed cells in under 1.5 s); rows over 2 MB are skipped. |
| SL-12 | Low | **Text from the school ends up in emails.** The school's name (and the class text) go into the email's subject and body as they are. A link or "call this number" in the school name reaches the parent in an email that looks like SportnNote's. | Fixed: `stripLinks` on the school name and class in the email. |
| SL-13 | Medium | **One mistaken tick can remove a whole school.** A one-class list uploaded in "Whole school" mode lists every other class as "not on this list". One tick on "Mark these 312 as left" ends hundreds of memberships and closes their class and House history. | Fixed: `needsLeaverConfirm` (20 or more, or a quarter of the students) asks with the number and percentage first. |
| SL-14 | Medium | **A typo in an admission number moves the wrong student.** If a row's admission number belongs to another student (for example "Rahul Shah" with Tara's number), it's trusted. Tara is moved to Rahul's class, and Rahul is never added. | Fixed: an admission number on a name that shares no word with the student's is a check (`admission_name`). |
| SL-15 | Medium | **Excel's 1904 date system.** Workbooks saved with that setting (older Mac Excel) store date serials 1,462 days apart from the usual system. Every date of birth comes out four years wrong, which puts children in the wrong age groups. | Fixed: `workbookPr date1904` is read, and `excelDate(serial, true)` adds 1,462 days. |
| SL-16 | Medium | **A name with no date of birth can mean the wrong child.** If neither the row nor the student on file has a date of birth, the same name alone counts as the same student. With common names (another "Rahul Kumar" joins), the new child is never added and the existing one is moved. | Fixed: a match on the name alone is the same student only in the same class or the next one up; otherwise it's a check. |
| SL-17 | Low | **No length limits.** A 1 MB name, or 1 MB text in any cell, is sent to the server and turned into a name key for every row. That wastes CPU and makes for odd preview text. | Fixed: names over 120 characters can't be read; other cells are cut to 60; the server cuts names to 200. |
| SL-18 | Medium | **Emails can be lost.** The edge function sends emails one after another, with no cap, and can hit the function's time limit part-way. The invites already exist, so running the list again won't email them ("asked before"), and those parents are never told. | Fixed: the app asks for 100 children a call (`PARENT_CHUNK`); the count of emails sent is shown, so any gap is visible. |
| SL-19 | High | **Already in the app: an admin can add any player to their community.** Any community admin can add any existing player (a child included) to it with "+ Add member". `guard_org_member` lets an admin insert any `player_id`. That puts the child in the admin's circle (full name, age) without the parent knowing, which goes around SL-01's parent approval. | **Deferred:** this hole already existed, outside this feature, and the founder needs to decide how to handle it. Raised with the founder, and passed to the database audit (`docs/security/audit-2026-10-27/`). |
| SL-20 | Low | **Swapping two admission numbers fails.** If students A and B swap numbers in a new list, the first save collides with the unique index. It's reported as "belongs to another student" even though the list is consistent. | Fixed: numbers being reassigned are deleted first, then saved. |
| SL-21 | Low | **A duplicate class entry.** If a parent approves after the child already joined the same class another way, the class history gets a second entry for that class. | Accepted: rare, harmless (an extra class entry), and visible in the class history. |
| SL-22 | Low | **Anyone holding the emailed code can answer** (a forwarded email). This is the same design as the parent-consent link. | Accepted: the same design as the parent-consent link; the code is 80 bits and lasts 30 days. |
| SL-23 | Low | **A stuck invite.** An admin can make a manual invite that looks like a list invite (`details.source = 'student_list'`). The child can't accept it, and the parent has no code, so it stays stuck until cancelled. | Accepted: only an admin can do it, and they can cancel the invite. |
| SL-24 | Medium | **Found by the simulation.** Two different children with the same name, their own admission numbers and no dates of birth were taken as the same row in the file. The second was skipped, so she showed up as a leaver. | Fixed: the in-file duplicate check uses the admission number, else name + date of birth, and the name alone only when a row has neither. |
| SL-25 | High | **Found by the simulation.** A child already on SportnNote elsewhere joined a school that already had a classmate with the same name but another date of birth. The row became a check, and answering "New student" created a duplicate profile instead of asking the parent. | Fixed: an exact name + date of birth + parent contact match elsewhere now comes before an admission number on another name or a same-name student with another date of birth, on the server (`roster_outside_match` first) and in the demo. |

## The simulation
`tests/sim-student-lists.test.mts` runs 500 seeded schools of 20–120 children over two school years.
- **Inputs:** common names; class written as "7", "VII", "Class 7-B" or "7B"; admission numbers and dates of birth present or missing; joiners, leavers and shortened names; children from other schools; lists in shuffled order.
- **Last run:** 103,016 rows. 35,770 created, 32,912 moved, 272 parents asked, 282 checks answered, 1,708 leavers, in about 11 s.
- **Invariants held:** one action per row; never matched to another child when an admission number or name + date of birth identifies them; no duplicate active memberships; no member lost; at most one open class, in order; leavers exactly the missing children; uploading the same list again changes nothing.
- **What it found:** SL-24 and SL-25, both fixed.
- **Not covered yet:** the database's concurrency under hundreds of simultaneous users. That needs staging (see `docs/engineering/quality-mandate.md`).
