# Cricket: one per-ball describe card with Done — break it first

2026-11-08, wave 2 of docs/sport-expert/defaults-on/PLAN.md (cricket.md items 6-8). Today two cards stack under the pad on the same ball: the shot card (wagon wheel, shot type) and the ball-detail card (pitch map, extra reason, false shot, speed, catch spot). Each has a small ghost Done/Skip at the top right, no saved state, and each remembers only one "last skipped" string. The fix is one `DescribeCard` per ball (`src/components/DescribeCard.tsx`): the shot section, then the detail section, one "✓ summary" line, one full-width Done (Skip when nothing is picked), the greyed "✓ Saved · … Edit" line, and a fresh card on the next ball. Every tag still saves on tap; Done only changes what is shown, except that it first saves a valid typed km/h. A T20 innings has ~120 balls, so the card never blocks the next ball: it sits under the pad and simply moves on. The pure parts live in `src/sports/cricket/describeBall.ts`. The bowler-type chips and the wicket flow are unchanged (they already finish clearly).

| # | Break | Kind | Fix |
|---|---|---|---|
| DK1 | Two cards on one ball, each with its own Done: two finishes per ball, and the scorer can't tell which one saved. | Clarity | One card per ball (`describeCard` in `index.tsx`): shot section, then detail section, one summary, one Done/Skip. `BallDetailPanel` has no Done of its own. Tested (source). |
| DK2 | The speed field has its own Save. Typing 132 and tapping Done drops it silently. | Data | Done first saves a valid, changed typed speed (`doneAction`), then greys the card. The typed speed counts in the summary, so the button reads Done, not Skip. Tested. |
| DK3 | A typed speed is lost when the next ball is scored (pad, voice, another scorer) before Save or Done. | Data | When the card moves to a new ball, a valid typed speed for the previous ball is saved to that ball (`flushOnMove`), if that ball is still in the log. Tested in the sim. |
| DK4 | Done / Skip is one "last key" string per card: undo then shows an earlier ball's card open again, and the two cards disagree. | State | Marks per ball in `useDescribeMarks` (a map), one key for the whole card. Tested. |
| DK5 | Undo of a ball, then a new ball: it has the same over.ball and delivery number, so it inherits the old ball's Done (and an unsaved typed speed would be saved onto it). | State | The key adds the device stamp `t` of the ball (`ballKey`). A re-scored ball has a new stamp, so a fresh card. A typed speed for a ball no longer in the log is dropped, never moved. Tested. |
| DK6 | Over boundary / new bowler: the last ball of the over must stay describable while the next bowler is picked, and the next over's first ball must not read its mark. | State | The key is per delivery, not per bowler or over; the card shows until the next delivery, as before. Tested. |
| DK7 | A wide or no-ball is re-bowled with the same stamp ("4.3"). The old shot key (stamp + striker + nb) is shared by two no-balls in a row, so Done on one hid the next. | State | The key uses the delivery ordinal `d` (wides and no-balls count), so every re-bowl is its own card. Tested. |
| DK8 | Free hit after a no-ball: the card could hide the free-hit ball or carry the no-ball's state. | State | The free hit is a new delivery, a new key; the free-hit banner is untouched. Tested. |
| DK9 | Change of innings: the last ball of innings 1 stays taggable until the chase's first ball; the chase's 0.1 could read innings 1's mark. | State | The key holds innings and side. Tested. |
| DK10 | Voice / quick scoring: a card that needs a tap would slow 120 balls. | Speed | Nothing in the card blocks the next ball; ignoring it costs zero taps, and a voice ball moves the card on (DK3 keeps a typed speed). Tested (source: the pad does not depend on the card). |
| DK11 | Merging the cards changes what is saved, so stats, careers, wagon wheel, pitch map or commentary shift. | Stats | The same SHOT and BALL_DETAIL payloads on each tap (`detailAction` builds the same payload the panel sent). Done/Skip/Edit send nothing else. Tested in the sim: same totals as saving every speed with Save. |
| DK12 | Old matches: balls scored before stamping have no `t`. | Replay | The key falls back to innings:side:delivery. No engine change, so replays are unchanged. Tested. |
| DK13 | Super Over: the card targets the nested mini-match. | State | Off during a Super Over, as before. Unchanged. |
