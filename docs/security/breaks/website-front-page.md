# Website front page (Stitch picks 18–24): break it (2026-11-08)

**Goal:** the sportnnote.in front page (`home` in `scripts/build-website.mjs`, styled by `website/styles.css`) takes the founder-approved parts of the Stitch design (`docs/design/stitch-picks/5-website-a.png`, `6-website-b.png`): the hero with a phone mock-up, a stat strip, "How it works", four audience cards, a sports grid, a child-safety banner and a final call-to-action band.

**Process:** quality mandate step 4. Listed **before** any fix. Each point then gets a failing test first (`tests/website-front-page.test.mts`).

| # | Failure | Status |
|---|---|---|
| W1 | **False claims copied from the mock-up.** The Stitch image says "COPPA & FERPA compliant", "Broadcast telemetry v2.4", "Zero config needed", "<60s match spin-up", "0 kB spectator install", "<100ms", "142 parents watching", "VAR/REV", "Official scorer verified". None is proven; a law-compliance claim is a legal risk. | **Fixed:** none of them is on the page; the test bans each phrase (and the word "compliant"). |
| W2 | **Wrong sports count.** The mock-up says 33; a typed number drifts the day a sport is added or removed. | **Fixed:** the count is `SPORTS.length` (from `SPORT_ORDER`, which tests already pin to every `src/sports/<id>/meta.ts`); the test counts the app's sport folders itself and compares with the stat strip, the headline and the grid. |
| W3 | **Unsupported sports in the grid.** The mock-up shows boxing, judo, darts, climbing. | **Fixed:** the grid is generated from the same `SPORTS` list; the test checks every tile is an app sport and every app sport has a tile. |
| W4 | **Untrue rule notes.** A per-sport note that the app does not do (e.g. "2m penalties" invented by the mock-up). | **Fixed:** each note is a short phrase taken from that sport's own scoring guide in `website/guides/`, and the tile links to that guide; the test checks every linked guide exists and every note has a guide. |
| W5 | **Broken links.** New audience cards, sport tiles and buttons could point at guides that don't exist, or at anchors no longer on the page (the header links `/#features` and `/#get`). | **Fixed:** the test resolves every `href` on the built page: a local path must be a built file, an anchor must be an `id` on the page, an outside link must be a config URL (app, Android, social, support email). |
| W6 | **SEO / sharing / structured data lost in the rewrite.** Title, description, canonical, Open Graph, theme colour, favicon and the Organization JSON-LD with `sameAs`. | **Fixed:** test asserts each is still there. |
| W7 | **HTML injection through config.** `appUrl` (and the `APP_URL` build override), `androidApkUrl`, `contactEmail`, `pricingLine` and social labels were partly inserted raw into `href="…"`; a quote in a value breaks out of the attribute. | **Fixed:** every config value on the page (and in the shared header) goes through `esc()`; the test builds with a hostile `APP_URL` / `SUPPORT_EMAIL` into a scratch folder (new `WEBSITE_OUT` override) and checks no raw markup appears. |
| W8 | **More than one main action per section.** The brand rule is one lime button per section; the old "Get the app" section had two. | **Fixed:** test counts `btn-primary` per `<section>`: never more than one; exactly one in the hero and in the final band. |
| W9 | **Child-safety wording overclaims.** "Names are masked" must match what the app does. | **Checked:** the server gives anyone outside a minor's circle a reduced card (initials, no photo, phone, city or school: `src/core/minorPrivacy.ts`), and under-18s need a parent's approval (`parent-guardian-consent` guide). The banner says exactly that and links the guide; no law is named. |
| W10 | **"No sign-up" overclaims.** Scoring without an account works for the guest sports; sharing the live link needs a (free) account. | **Fixed:** the hero button keeps the approved "no sign-up" label (true for starting a game, `GuestGameScreen`); step 3 says you sign up when you share. |
| W11 | **Pricing drifts.** "Free while we're new" typed into the page would stay after pricing changes. | **Fixed:** the stat comes from `pricingLine` in `website/config.json` (text before the ";"), the rest is shown as its label. |
| W12 | **Overflow at 375 px.** A wide phone mock-up, a long headline in the condensed face or a fixed-width grid causes horizontal scrolling. | **Fixed:** grids use `minmax(…, 1fr)` / single columns on small screens, the phone mock-up is `max-width` + `width: 100%`, long words wrap; checked in the preview at 375 px and 1440 px (`scrollWidth == clientWidth`). |
| W13 | **Contrast.** Lime text on cream, muted text on the green band. | **Fixed:** lime is only a fill with dark ink (`#14181D`), or text on the deep green; band body text is the hero cream/muted pair the app already tests (`tests/a11y-contrast.test.mts`). |
| W14 | **The mock-up reads as a real match / real child.** | **Fixed:** demo names only (Red House, Blue House, Rohan Nair), the mock-up is `aria-hidden` and has no photo. |
| W15 | **Build races in tests.** Two test files building into the same `website/dist` at once can delete each other's output. | **Fixed:** the new test builds into its own scratch folder through `WEBSITE_OUT`. |

## Results
`tests/website-front-page.test.mts`: 30 tests, all passing. Full suite 7,752 tests (7,750 pass, 2 existing todos, 0 failing); `tsc --noEmit` clean. Preview checked at 375 px and 1440 px: no horizontal scroll (`scrollWidth == clientWidth`). Not published.
