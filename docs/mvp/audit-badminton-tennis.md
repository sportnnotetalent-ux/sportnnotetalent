# MVP audit: badminton and tennis scoring

Date: 2026-10-31. Scope: the scorer's seat at an amateur game (MVP.md). Code read on branch `feat/sport-formats-and-scoring`; nothing changed.

## Summary

**Counts (unique findings):** P0: **1** · P1: **10** · P2: **13**.
Ten findings (7 P1, 3 P2) are shared by both sports (same code), so they appear in both tables. Per table, P0 / P1 / P2: badminton 0 / 8 / 7; tennis 1 / 9 / 9.

**The 3 most important things**
1. **Tennis P0: a custom "Games per set" never moves the tiebreak.** "4 (short)" still plays the tiebreak at 6-6, not 4-4. "8 (pro set)" ends the set 7-6 after a tiebreak at 6-6. Fast4 changed to 6 games still breaks at 3-3. A short-sets match cannot be scored correctly or finished.
2. **The point buttons don't stay put or mirror the court.** They jump when banners, alerts and pickers appear or vanish. They never swap when players change ends. Both sides can get the same colour. Doubles buttons show initials ("RKAS"). In doubles, a press longer than 0.35 s scores nothing. Together these are the main way a hurried scorer taps the wrong side or loses a tap.
3. **Wrong-format traps with no way out.** Tennis "Match tiebreak (to 10)" makes the whole match one tiebreak. The common club formats (2 sets + match tiebreak with advantage, one set, short sets) are missing or mislabelled. The format locks once the match is live, so a wrong pick means ending the match and starting again after the 5-minute restart window.

**How this was checked:** I read the engines, shared racket helpers, set-up and scoring screens. I ran 8 existing test files (124 tests, all pass). Node scripts confirmed every edge below: 20-20, the 29-all golden point, deuce/advantage, no-ad, the Fast4 sudden death, a match ending on a set tiebreak or a match tiebreak, and the custom-format bug. I also fuzzed 300 random matches per preset (singles and doubles). Every preset finished, and the badminton doubles server and court always agreed with the engine.

## Already good

- **Prior generic findings G1–G8 are fixed.** G1: Undo sits beside the controls, and End / Restart / Cancel are at the bottom behind a confirm (the tennis near-miss). G2, G3, G5: confirms. G4: the result is held about 60 s and Undo cancels it. G6: keep-awake. G7: haptics on tap and on Undo. G8 needed nothing.
- **Prior depth items are shipped:** the result reads correctly after the end (not 0-0); tiebreak scores show as 7-6(4); double faults are a first-class point; one-tap Ace / Double fault for the server; the Slam deciding set; badminton doubles server and receiver by name; doubles scoring without crediting a player; change-ends and interval cues; misconduct; durations; "ret." marks.
- **Toss, colours and editing:** there is no silent "home serves" default (the toss is required). The two point buttons are big and in team colours, with SERVING marked. Every tap is undoable step by step, and Undo names what it removes. The timeline editor confirms removals. GAME / SET / MATCH / BREAK POINT are derived from the engine itself.
- **Defaults:** BWF 21 best of 3 and best-of-3 tennis are sensible. Point-detail tracking is off by default, so the screen stays two buttons.

## One risk outside these tables

`TESTING_ALLOW_UNVERIFIED = true` (core/eligibility.ts:45) is marked "must be false before go-live". Flipping it hides every unverified adult (no DOB, unverified mobile) from the scoring roster, friendlies included. That would remove name-only friends: no auto-credit and no doubles server names. Decide the friendly rule before flipping it.
