The user wants a living reference document capturing all the work done on [[sportfolio-overview]]. It lives at `sportfolio/DEVLOG.md` (repo root) — a human-readable changelog + quick-reference + demo-match registry + known-limitations.

**Why:** they want a durable, openable record they can refer back to later (not just my private memory files).

**How to apply:** treat DEVLOG.md as a continuously-maintained artifact — **append/update it whenever a meaningful chunk of work ships or a demo match is set up**, in the same batch as the code + memory updates. Keep entries dated (absolute dates), note the change + key files + verification status. Mirror the level of the existing entries; don't let it go stale. It complements (not replaces) [[sportfolio-product-mandate]] and [[sportfolio-live-scoring-gaps]].
