**Standing goal (set 2026-07-09):** take Sportfolio live within **45 days** — Day 0 = 2026-07-09, target **pilot** launch ≈ **2026-08-23**. Full plan delivered as an Artifact (launch-plan-v1): https://claude.ai/code/artifact/48d941e0-b761-4079-9287-698cdbbf8241

**Why / how to apply:** all future work should be weighed against this date. The launch is **three parallel tracks**, not just product: **A) Product depth** (the user's list — sport scoring parity, athletics + new sports, organizer flows, UX polish), **B) Platform readiness** (the big hidden lift — the app is still **demo mode**/in-memory; Supabase is scaffolded but NOT the live source of truth; needs real DB+migrations+RLS+realtime+backups, real auth, offline/sync hardening, analytics, crash reporting), **C) Launch & compliance** (app-store accounts+review lead time, Privacy/Terms, India **DPDP Act** + **guardian consent for minors**, content moderation, closed beta, support, monitoring). B and C start Day 1.

**Honest scope call I gave:** 45 days is realistic for a **pilot** (a few real Bengaluru schools), not a full open all-sports launch. Recommend **Android + web first, iOS fast-follows**; fixed sport set; phase gates.

**Decisions LOCKED (2026-07-09):** (1) **iOS + Android native apps only — NO web app** (maybe a marketing/contact site later; both store reviews are on the critical path, no web fallback). (2) **Deep sports at launch: football, cricket, basketball, kabaddi, tennis, badminton**; rest usable-basic, deepened post-launch (real remaining lift ≈ tennis + badminton + polish, since football is done and cricket/basketball/kabaddi are close). (3) **Solo founder, fully bootstrapped** — minimize spend but NO compromise on ability to scale into year-one data growth (use managed free-tier services that scale on same architecture; pagination/indexing/archiving; capacity, not money, is the binding constraint). (4) **Controlled pilot** first. (5) **No monetization year one** (value-first), then monthly subscription or ads — keep a clean subscription seam in the data model, don't build billing yet. Plus user added: **in-app support tickets + YouTube how-to/tutorial videos**, built in P6 just before launch once flows are frozen.

**Still open:** pilot cohort (which/how many schools + when they can test the P5 beta); 2-3 success KPIs; confirm Day 0.
